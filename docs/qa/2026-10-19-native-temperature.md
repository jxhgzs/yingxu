# 剪映 5.9.0 温度与色调原生对照

2026-10-19。继 [REA 数学恢复](2026-10-19-rea-temperature.md) 后完成有限原生实验。候选仍未接产品的导入、UI、GPU 或导出；本轮交付功能继续聚焦有声曲线 GPU。

## 当前结论

原生 UI 的色温使用草稿 **`type=temperature`**，色调使用 **`type=tone`**。两者 `version=v3`、`sub_type=none`，资源路径都为 `DefaultAdjustBundle/combine_adjust`，UI ±50 对应 value ±1。独立包的 `tone_intensity` 和合并包的 `tint_intensity` 仍是不同的资源 event key；内部 `MaterialPictureAdjust::get_hue()` 的名称不是草稿 type，禁止仅按名称猜映射。

独立重写白点矩阵后，在18个静态色块的 H264 编码链比较中，最大误差为灰阶4、彩色3个8位LSB。亮度+50、色温+50 的顺序探针支持“先亮度、后温度”；反序有显著偏差。结果支持继续集成候选，但不构成整应用或逐像素 1:1 验收。

## 数学、编码链与顺序分别核对

数学比较由源 Rec.709 limited YUV 经 zscale 保持 Rec.709 transfer/primaries 转为浮点编码RGB，传入独立候选，再与原生最终RGB比较。最大灰阶4.7062、彩色3.8474 LSB；中性源本身经原生导出已有灰阶2.1233、彩色2.8451 LSB差异。这个层面含编解码量化，不能将全部差异归为矩阵误差，也没有通过调矩阵常数拟合输出。

另实际执行隔离的 FFmpeg 编码链：相同浮点解码→候选3×3 colorchannelmixer→独立2行单位LUT作clamp→RGBA→Rec.709 limited YUV420→libx264 veryfast/CRF18/30fps。亮度组合在温度矩阵前复用已验证的独立亮度LUT。其9例最大差列于上表。这是实际H264编码链探针，**不是已经接入产品的 renderer，也不是 GPU texture readback**；脚本和滤镜留在 ignored `artifacts/qa/native-temperature-next/`。

原生亮度+50/色温+50 的正序隔离编码链误差为灰阶3、彩色2；“先温度、后亮度”的反序纯数学误差为灰阶76.6820、彩色65.9062。结合原生JSON中 brightness v2、temperature v3 均指向 combine_adjust，支持此版本此组合中温度在亮度之后。不能据此外推所有未知特效的全局排序。

## 中性恢复的边界

初始0与恢复0在第30帧的18个色块完全相同，且该帧全幅2,764,800个RGB通道样本逐一相同。继续比较60帧RGB哈希时发现仅第5帧不同，其全幅最大21 LSB、平均绝对差0.154876 LSB，112,915个通道样本不同。原生解码YUV帧哈希也有差异；原因本轮未建立，因此没有把两次完整视频标为逐帧一致，也没有将异常自动归因于编码器或矩阵。原始观测保留在 native-patches.json。

后续接产品前仍须验证真实WebGL矩阵、alpha边界、更多分辨率/颜色标签、连续画面和时序，以及导入白名单。当前只是有限色卡结果和候选准备完成；完整1:1尚未完成。
