# 原生对比度逐色块核验

日期：2026-10-19，固定剪映专业版5.9.0。原生界面操作与导出由主任务完成，本子任务独立读取五个真实 MOV、对应原生 JSON 和既有自制色卡，未打开/修改原生 app、GPU/UI、生产工程或共享效果公式。

## 原生观测与复现

输入为 `evidence/2026-10-19-color-patches/source.mp4`，SHA-256 `7e035a05d9b0cefc89a12b92ce3c3e899010f1b8365203cce19e1c84a6606fad`。原生五份导出位于本机 Downloads 的 `yingxu-native-{contrast-plus50,contrast-plus25,contrast-minus25,contrast-minus50,brightness50-contrast50}-20261019.mov`，每份1280×720、30fps、60帧、2秒，输出色彩709、tv。完整 MOV 未加入 Git。

原生单变量 UI ±50/±25 对应 `contrast`、`version:v3`，原始 value 为 `1 / .5 / -.5000000000000002 / -1`；组合为 `brightness:v2:value1` 与 `contrast:v3:value1`。负25的浮点尾数保留在观测，不改写成“原JSON精确-.5”。效果资源代际为 `combine_adjust`，完整 JSON 仍在 ignored `artifacts/qa/native-adjust-next/`；公开证据只存非执行参数摘要。

`evidence/2026-10-19-contrast/native-patches.json` 保存每份原生 MOV 的 SHA-256、字节数、实际 ffprobe/帧数、效果摘要及第30帧12灰阶/6彩色色块的RGB数组。取样坐标与上一轮一致，灰阶y180、彩色y540，各区间水平中心；使用FFmpeg默认rgb24解码作为既有golden口径，不把截图颜色当buffer值。

## 公式与完整渲染分别比较

CPU候选先用 zscale 将原始源YUV按709/limited解码为gbrpf32le，保持709 transfer/primaries，再应用独立 `applyColorAdjustments`，得到未经最终编码的RGB。该浮点结果与原生编码后RGB存在不同量化环节，误差单独列出，不与完整链容差混同。

完整链从 `render()` 进入，实际经过浮点解码、65536项LUT、RGBA合成、709/tv编码、再解码取样。原生对照最大绝对误差如下（LSB）：

| 原生设置 | CPU对原生灰阶/彩色 | 完整链灰阶/彩色 | 验收 |
| --- | --- | --- | --- |
| 对比度+50 | 2.775227 / 3.131695 | 1 / 2 | 满足2/4 |
| 对比度+25 | 2.262920 / 3.751110 | 2 / 2 | 满足2/4 |
| 对比度−25 | 2.568556 / 3.595670 | 2 / 3 | 满足2/4 |
| 对比度−50 | 2.370000 / 3.954205 | 2 / 3 | 满足2/4 |
| 亮度+50、对比度+50 | 3.721513 / 4.216922 | **3 / 3** | **未满足灰阶2的原阈值** |

组合差异出现在gray[2]：完整链 `[44,44,44]`，原生 `[41,41,41]`。回归中将组合单独标为当前灰阶3/彩色4限值，不能把五组笼统称为原2/4全部通过；四个单变量仍保持原2/4阈值。

同输入比较组合顺序：亮度→对比度的CPU最大差为4.216922，而对比度→亮度最大差为143.798765；反顺序有明显错误，当前产品顺序保留亮度→对比度。该对照支持顺序选择，但不证明该组合已经逐像素一致。

## 组合差异的独立探针

首先核对同一个灰阶[2]的实际解码：

| 文件 | 原始Y | 默认rgb24 | 保持709的float RGB×255 |
| --- | --- | --- | --- |
| source | 43 | 30 | 31.438354 |
| 原生零调节 | 43 | 30 | 31.438354 |
| 原生亮度+50 | 86 | 80 | 81.506842 |
| 原生亮度+50、对比度+50 | 53 | 41 | 43.082191 |

原生零调节与源在此Y值完全相同，不能把其默认rgb24值30直接当成效果公式接收的浮点输入。亮度CPU预测为83.165037（未编码），相对于原生亮度解码float的81.506842已有约1.66级差异，组合的非线性对比度会进一步放大该区间的输入差异。

没有调整任何产品参数或公式。仅在ignored探针内独立生成候选LUT，分别尝试“进入亮度前量化8bit”和“亮度后、对比度前量化8bit”，再通过相同完整编码链比较：

| 独立假设 | 组合灰阶/彩色最大差 |
| --- | --- |
| 当前保留float | 3 / 3 |
| 进入亮度前round到8bit | 1 / 3 |
| 进入亮度前floor到8bit | 1 / 2 |
| 亮度后round到8bit | 3 / 3 |
| 亮度后floor到8bit | 3 / 3 |

结果保存于 `quantization-hypotheses.json`、`decode-comparison.json`。本组观察更支持“输入精度/前置颜色转换差异”的待验证解释，不能证明目标确实存在某一种8bit量化节点；两种输入量化都改善，当前证据不能区分round/floor，也未覆盖其他九组效果或动态纹理。没有为通过阈值把产品改成上述候选，方程误差也尚未被独立排除。

复现脚本保留于 ignored `artifacts/qa/native-contrast-verify/{verify,decode-probe,quantization-probe}.mjs`。正式回归：`node --test test/color-contrast-native-render.test.ts`，包括四单变量2/4、组合显式3/4限制，以及对原生组合顺序的独立检验。没有原生音频听审、HDR、其他分辨率、不同素材或全取值区间的1:1结论。
