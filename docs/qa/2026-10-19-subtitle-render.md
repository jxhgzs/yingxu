# 批量字幕原生合成验证

2026-10-19，实施 `2026-10-19-subtitle-integration.md` Task 2。只改媒体合成和对应测试，不修改字幕解析、命令或界面。

## 实现

- 连续文本图层共用一个ASS文件及一条 `subtitles` 滤镜；每个可见片段使用独立Style，事件Layer按原始图层次序递增。
- 中间遇到图片/视频图层立即结束文本组，媒体前后各自生成文本组。不会将被媒体遮挡的文字移到最上层。
- 继续按精确有理数计算帧的ceil边界，再转换为ASS的floor厘秒。文本动画继续通过源时钟求值，复用原来的位置、缩放、旋转和透明度逐输出帧事件。
- 图限制为5000个文本片段和300个媒体片段，时长仍最多1小时。单文本组最多100000条实际事件，超出在FFmpeg启动前抛出 `TEXT_RENDER_EVENT_LIMIT`。只含音量动画的文本不会无意义地生成逐帧视觉事件。

## 实测

`node --test test/subtitle-render.test.ts`：3项通过。

- 5000条字幕，ASS中5000条Style、5000条Dialogue，实际原生导出前1秒，只有1条字幕滤镜；最新运行约0.89秒。该耗时只对应前1秒输出，不是完整5000条字幕全长编码的性能。
- 图构造允许同时5000文本与300媒体（5300图层），5001文本、301媒体以及超过1小时均明确拒绝。
- 同位置红/蓝文本保持后者覆盖前者；中间插入不透明绿色媒体后，下层红蓝文字都不泄露，上层中文两行在上下区域实际出现。
- 1小时、30fps的动态文本产生108000帧事件，明确拒绝；没有运行1小时输出。

`node --test test/compositing.test.ts test/animation-render.test.ts`：已有6项原生回归通过，含30/60/30000÷1001fps单帧可见区间、文字动画位置和透明度，以及原媒体/音频行为。

`npm run typecheck` 曾完整通过；并行模块仍在修改，最后一次复查仅报告 `RelinkDialog.vue` 的 `asset.relink` 尚未接入Command类型，已通知父任务完成后统一复查。首次检查也曾遇到该模块尚未落盘的临时缺文件。媒体实现及新增测试未出现类型错误。
