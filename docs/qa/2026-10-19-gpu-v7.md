原始 GPU→编码 MP4 在高频 RGB 网格上最大221、mean最高约24.54，不能宣称二者像素一致。直接把 CPU 理想输入量化再走相同编码，对非零调节仍有 max15–22；因此不能简单把一切差异都归咎于编码。正式编码前实际 RGBA 与 GPU 尚有 0–2 LSB 差异，全部调节组合有147个 RGB 样本差2。精确抽取该正式编码前 RGBA 再编码，7组均逐像素0，确认后续编码差异完全可复现。

进一步隔离：FFmpeg7.1.1 同一 PNG→gbrapf32le（不应用任何调节），与原始8bit/255 已有 max1.1050565 / mean.4996580 LSB，direct format 与经 RGBA 转换均复现；16bit 中间格式没有解决。这表明图像到 float 的格式转换本身含输入残差，但尚未唯一识别内部 swscale 归一化/转换路径，不据此修改产品、拟合 gamma 或扩大原生门槛。应保留为小量正式离线与 GPU 的真实差异。详见 float-source-isolation.json。

## 资源与取消

实际创建 WebGL context 1、AudioContext 0；19次文字请求，5组重复 descriptor key。取消测试刻意让旧请求在成功响应后仍延迟350ms并忽略abort，切换新工程后 oldSignalAborted=true，额外绘制 0，新工程保持frame0/time0/cache1，pass=true。

dispose 后 cachedMedia/framebuffers=0，contextlost 是显式 releaseContext 引发，不能当作上下文恢复测试通过。精确请求时序、key、manifest、原始帧完整保留于 result.json。
